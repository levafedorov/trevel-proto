# Версия A — поведение на мобильных (спека для UX/UI)

> Дополнение к [Версии A](./version-a-sectioned.md). Что заложить в мобильный макет.

## Итог

**Версия A — самая безопасная из трёх для мобильных.** Это одна линейная колонка
секций, а линейный стек по своей природе адаптивен: здесь нет scroll-spy, табов и
sticky-навигации (это было в версиях B/C), которые сложно вести на узком экране.
**Структурных блокеров нет.** Нужно осознанно спроектировать три вещи ниже.

---

## ① Кнопка брони — главный мобильный вопрос

На десктопе `BookingSidebar` — это sticky-колонка справа. На мобиле колонки нет, и
сайдбар уезжает в самый низ страницы — кнопка «Забронировать» оказывается погребена
под 7 днями программы.

**Решение:** на мобиле сайдбар превращается в **зафиксированную нижнюю панель**
(sticky bottom bar): цена + кнопка «Забронировать», всегда на экране.

```
┌──────────────────────────┐
│  контент секции…         │
│  … (скроллится)          │
│                          │
├──────────────────────────┤  ← fixed к низу вьюпорта
│  €1000   [ Забронировать ]│
└──────────────────────────┘
```

Состояния кнопки те же, что на десктопе: активна / «Скоро» (disabled) / «Лист ожидания».

## ② Длинная программа (7 дней) — аккордеон

`OfferItinerary` — самая длинная секция. На мобиле это очень много скролла.

**Решение:** дни — **сворачиваемые (аккордеон)**. Открыт один день, остальные свёрнуты
(заголовок дня + тема видны, содержимое раскрывается по тапу). Архитектуру не меняет —
`ItineraryDayCard` просто получает состояние collapsed/expanded.

## ③ Многоколоночные блоки → в одну колонку

На десктопе — в два столбца, на мобиле схлопываются в один:

| Секция | Десктоп | Мобайл |
|---|---|---|
| Hero | заголовок и цена в ряд | заголовок, под ним цена (стопкой), меньше кегль |
| «Что входит / не входит» | 2 колонки | 1 колонка |
| Highlights (сетка) | 2 колонки | 1 колонка |
| **`OfferDepartures` (даты/места/цена)** | таблица допустима | **стопка карточек, НЕ таблица** (широкая таблица не влезает в 360px) |
| Галерея | грид | свайп-карусель |

## Общая гигиена (инструменты уже в стеке)

- Изображения — через `@nuxt/image`: адаптивные размеры (`sizes`), `loading="lazy"`,
  фиксированные пропорции, чтобы не было скачков layout (CLS).
- Тап-цели ≥ 44×44px (кнопки, ссылки в навбаре, стрелки карусели).
- Проверить на 360px ширины (базовый мелкий Android) и на 390–430px (iPhone).
- Sticky-навбар сайта + нижняя панель брони не должны перекрывать контент — заложить
  нижний `padding` у страницы на высоту панели.
